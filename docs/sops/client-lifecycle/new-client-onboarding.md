# Standard Operating Procedure: New Client Onboarding

> **Part of the JS Solutions Standard Operating Procedures**

---

# Purpose

This Standard Operating Procedure (SOP) defines the process for onboarding a new client after a proposal has been accepted.

The objective is to ensure every client receives a professional, organized, and consistent experience while preparing the project for a successful delivery.

A successful onboarding process establishes trust, sets expectations, and provides the foundation for the entire project.

---

# Scope

This SOP applies to all new JS Solutions clients regardless of project size or service.

Examples include:

- Website Development
- Local SEO
- AI Automation
- Analytics
- Custom Software

---

# Responsibilities

## Project Manager

Responsible for:

- Coordinating onboarding
- Scheduling meetings
- Tracking required information
- Managing client communication

---

## Technical Lead

Responsible for:

- Reviewing technical requirements
- Identifying risks
- Confirming technical feasibility
- Preparing the development environment

---

## Client

Responsible for:

- Providing requested information
- Granting required access
- Reviewing documentation
- Participating in kickoff meetings
- Providing timely feedback

---

# Prerequisites

Before onboarding begins:

- Proposal signed
- Initial payment received (if applicable)
- Scope approved
- Timeline approved
- Primary client contact identified

Do not begin project work until these requirements are satisfied.

---

# Procedure

## Step 1 — Confirm Project Approval

Verify:

- Proposal signed
- Scope approved
- Budget approved
- Timeline approved

Record the approval date.

---

## Step 2 — Create Project Workspace

Create the project workspace.

Examples include:

- GitHub repository
- Project folder
- Documentation folder
- Shared client folder
- Project management workspace

Record all project links.

---

## Step 3 — Create Project Documentation

Initialize project documentation.

Create:

- Project Overview
- Timeline
- Meeting Notes
- Risk Log
- Decision Log

Ensure documentation follows JS Solutions standards.

---

## Step 4 — Send Welcome Email

Send a welcome email that includes:

- Thank you message
- Project summary
- Primary contact information
- Next steps
- Discovery meeting scheduling link
- Expected timeline

The objective is to reassure the client and establish clear communication.

---

## Step 5 — Request Required Access

Collect access to:

- Domain registrar
- DNS provider
- Website hosting
- Existing website
- Google Business Profile
- Google Analytics
- Google Search Console
- Social media accounts (if applicable)
- CRM or third-party systems (if applicable)

Document all credentials securely.

Never store passwords in unsecured documents.

---

## Step 6 — Schedule Discovery Meeting

Schedule the project discovery meeting.

Invite:

- Primary client contact
- Key stakeholders
- Project Manager
- Technical Lead (if applicable)

Share the meeting agenda in advance.

---

## Step 7 — Review Business Goals

Document:

- Business objectives
- Success metrics
- Primary audience
- Competitive landscape
- Project priorities

Ensure all stakeholders agree before continuing.

---

## Step 8 — Identify Risks

Review potential project risks.

Examples:

- Missing content
- Tight deadlines
- Third-party dependencies
- Limited technical access
- Scope uncertainty

Document mitigation strategies.

---

## Step 9 — Confirm Communication Plan

Define:

- Primary communication channel
- Meeting schedule
- Response time expectations
- Progress update frequency
- Escalation contacts

Ensure both parties understand communication expectations.

---

## Step 10 — Mark Project Ready

Confirm:

- Documentation complete
- Required access received
- Discovery meeting scheduled
- Client informed
- Internal team notified

Project status:

☐ Ready for Discovery

---

# Quality Standards

Successful onboarding should:

- Feel organized
- Build client confidence
- Eliminate uncertainty
- Clearly communicate expectations
- Prepare the team for Discovery

Every client should receive the same high-quality onboarding experience.

---

# Common Issues

| Issue | Resolution |
|--------|------------|
| Missing account access | Follow up immediately with the client |
| Incomplete scope | Schedule clarification meeting |
| Delayed approvals | Adjust project timeline |
| Missing content | Begin content collection process |
| Unclear decision maker | Identify primary stakeholder before proceeding |

---

# Success Criteria

This SOP is complete when:

- Proposal is accepted
- Project workspace created
- Documentation initialized
- Client welcomed
- Required access received
- Discovery meeting scheduled
- Risks documented
- Communication plan established

At this point, the project is officially ready to begin Discovery.
